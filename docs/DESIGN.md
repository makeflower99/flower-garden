# Design

Design version: **1** (docs/CHANGELOG.md의 버전과 동일하게 유지)

## 톤앤매너
- **미니멀 우선**: 데이터/AI 채용 담당자·교수 모두 정보 밀도가 높은 문서를 빠르게 훑는다. 장식보다 위계(제목/메타/본문)가 또렷한 타이포 중심 레이아웃을 우선한다.
- **makeflower 모티프는 절제해서 사용**: 사이트 정체성(도메인/브랜드)과의 연결을 위해 라인아트 꽃 모티프를 파비콘 + 헤더 로고 마크 + 프로필 placeholder에만 적용한다. 본문 콘텐츠에는 꽃 장식을 넣지 않아 "귀여운 사이트"가 아니라 "담백한 전문 포트폴리오"로 읽히게 한다.
- **사진 유무 모두 자연스럽게**: `assets/img/avatar-placeholder.svg`가 은은한 원형 라인아트로 존재해, 실제 사진이 없어도 레이아웃이 비어 보이지 않는다. 나중에 사진을 추가하면 `data/profile.json`의 `photo` 경로만 바꾸면 된다.

## 컬러
`assets/css/main.css`의 `:root`에 CSS 변수로 정의 (톤 조정 시 여기만 수정):
| 변수 | 값 | 용도 |
|---|---|---|
| `--color-bg` | `#faf9f6` | 배경 (따뜻한 오프화이트) |
| `--color-surface` | `#ffffff` | 카드 배경 |
| `--color-text` | `#23231f` | 본문 |
| `--color-text-muted` | `#6b6b62` | 메타 정보 |
| `--color-accent` | `#7a8c66` (세이지 그린) | 포인트 컬러, 로고, 활성 토글, 링크 |
| `--color-accent-2` | `#b9757a` (더스티 로즈) | 보조 포인트 (추후 grad 모드 강조 등에 확장 가능) |
| `--color-border` | `#e6e2d8` | 구분선/테두리 |

세이지 그린을 기본 포인트로 선택한 이유: 꽃/식물 모티프와 자연스럽게 연결되면서도 데이터/AI 업계에서 흔한 톤(차분하고 신뢰감 있는 색)이라 이직/대학원 어느 맥락에서도 튀지 않는다.

## 타이포그래피
- 본문: 시스템 산세리프(`-apple-system, "Segoe UI", "Pretendard", "Noto Sans KR"`) — 별도 웹폰트 로드 없이 각 OS의 가독성 좋은 기본 글꼴을 사용해 로딩 비용 없음
- 태그/스킬 배지: 모노스페이스(`--font-mono`) — 기술 스택을 코드처럼 보이게 해 데이터/AI 정체성 강조

## 레이아웃 구조
```
헤더 (sticky) — 로고+이름 / 모드 토글 / PDF 저장 버튼   [no-print]
히어로 — 사진(선택) / 이름 / 타이틀 / 모드별 요약문 / 연락처 링크
섹션들 (sectionOrder[mode] 순서, summary 제외)
  각 섹션: 제목 + 카드 리스트
푸터                                                    [no-print]
```
- 컨테이너 최대 너비 `--wrap-width: 760px` — 이력서 특성상 한 눈에 스캔하기 좋은 좁은 컬럼 유지
- 카드(`.card`)는 테두리+라운드 코너로 통일, `emphasis: "high"` 항목만 포인트 컬러 테두리로 구분

## 모드별 시각 차이
- 콘텐츠 자체(섹션 순서/노출/문구)가 모드에 따라 달라지는 것이 핵심이며, 시각 스타일은 두 모드에서 동일한 디자인 시스템을 공유한다 (일관된 브랜드 인상 유지)
- 모드 토글 버튼만 활성 상태를 포인트 컬러로 표시해 "지금 어떤 버전을 보고 있는지"를 명확히 함

## Print(PDF) 레이아웃
- `.no-print` 요소(헤더, 푸터, 토글, PDF 버튼)는 인쇄 시 제거
- 배경은 흰색, 텍스트는 검정에 가깝게(`#000`/`#333`) — 잉크 절약 + 스캔 가독성
- 링크는 `href`를 괄호로 텍스트에 병기해 종이 이력서에서도 URL 확인 가능
- `.card`, `.section`에 `break-inside: avoid`로 카드가 페이지 중간에 잘리지 않게 함

## 향후 디자인 변경 워크플로
디자인 시스템(컬러/레이아웃/컴포넌트 구조)을 바꿀 때는:
1. 이 문서를 먼저 갱신 (버전 번호 올리기)
2. `docs/CHANGELOG.md`에 Design 항목 추가
3. `assets/css/*.css`에 반영

`docs/ARCHITECTURE.md`(데이터/렌더링)와 이 문서(디자인)는 서로 다른 관심사이므로, 스키마 변경과 디자인 변경이 같은 시점에 일어날 때는 `docs/CHANGELOG.md`에서 함께 확인해 서로 참조가 깨지지 않는지 점검한다.
